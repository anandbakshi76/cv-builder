# CV Builder

Single-page, click-to-edit CV for a UK/US-style student CV. Next.js (App Router) + TypeScript + Tailwind v4. No backend, no login: data lives in `localStorage` under `cv-builder:v1`.

## Project phases and working rules (owner's instructions, apply to every later prompt)
The project is built in 6 phases. **Phase 1 is complete and frozen** as the base: see `docs/PHASE-1-FROZEN-BASELINE.md` and git tag `phase-1-base`. **Phase 2 (View mode, print options, ATS-friendly PDF) is complete**: git tag `phase-2`, details in `docs/2026-10-03-cv-display.md`. **Phase 3 (skill filter in View mode) is complete**: git tag `phase-3`, details in `docs/2026-10-03-cv-filtering.md`. **Phase 4 (versions, export formats, photo upload, GitHub readiness) is complete**: git tag `phase-4`, details in `docs/2026-10-03-export-formats.md`. **Phase 6 (Job Matcher: job description upload, AI match analysis, aligned versions) is built**: details in `docs/2026-10-03-job-matcher.md` and `docs/2026-10-03-job-matcher-examples.md`. **Phase 5 (portfolio website creation and integration) must not alter the CV builder's design, functionality or behaviour in any negative way**: build it additively (new routes/components/files), leave the editor, saved data and exports as they are, and ask before touching anything existing. The same rules apply to everything built so far. Work in manual mode, prompt by prompt, until prompt/phase 6 is done:
1. **Additive and non-disruptive** (new, useful functionality that leaves existing behaviour, sections, settings, themes, data and look unchanged): go ahead and build it.
2. **Anything that changes, removes or could negatively disrupt existing Phase 1 behaviour** (settings, sections, themes, data model, saved data, layout, defaults): do NOT make the change. First review and analyse it, tell the owner the impact, and ask for approval.
3. Keep saved data compatible: new fields need defaults and a `lib/migrate.ts` step; never rename or drop existing fields or the `cv-builder:v1` key without approval.
4. Verify with `npx tsc --noEmit` (and `npm run build` for larger changes) and update `CLAUDE.md` / `docs/` for what was added.

## Commands
- `npm run dev` — http://localhost:3000
- `npm run typecheck` — `tsc --noEmit`

## Structure
- `app/page.tsx` — renders `<CVEditor />`; `app/globals.css` — Tailwind import, `.editable` styles, print CSS
- `components/CVEditor.tsx` — the whole page: toolbar (save status, theme swatches, Edit/View, Print, Reset), gradient header banner, all sections in CV order, plus `Card`/`CardHead`/`TagsRow` helpers (template-style grey card with accent bar, bold title, accent subtitle, white date pill)
- `components/Editable.tsx` — in-place text (uncontrolled `contentEditable="plaintext-only"`); also owns `EditContext`. In View, an empty `Editable` renders nothing. Supports `onEnter` / `onBackspaceEmpty` / `autoFocus` for bullets
- `components/BulletList.tsx` — bullet editor (Enter = next bullet, Backspace on empty removes)
- `components/DateField.tsx` — `DateField` (native month calendar, `type="month"`), `DateRange` (from/to + "Ongoing" checkbox storing `"present"`), `DatePill`
- `components/SocialIcon.tsx` — brand-coloured circular icons + `PLATFORMS`
- `components/TagList.tsx` — comma-separated tags; clicking a tag toggles a highlight (hook for future filtering)
- `components/PhotoUpload.tsx` — square-crops and resizes to a 240px JPEG data URL
- `components/Section.tsx` — `Section` (hidden when `visible` is false), `AddButton`, `RemoveButton`, `Label`
- `lib/themes.ts` — colour themes (gold, indigo, emerald, rose, amber, slate), applied as CSS vars `--accent`, `--accent2`, `--tint` on the root wrapper
- `lib/types.ts` — data model; `lib/defaults.ts` — defaults, blank-item factories, storage key; `lib/cv.ts` — `has.*` content checks, graduation calc
- `lib/health.ts` — "CV strength" score, advisories (page count, date of birth, UK spelling) shown from the toolbar
- `lib/dates.ts` — month formatting and legacy-date parsing; `lib/migrate.ts` — turns any older saved shape into the current `CVData`
- `lib/useCV.ts` — loads (via `migrate`) after mount, debounced (400 ms) save, `saved | unsaved | error` status, flush on `pagehide`

## Section order (do not reorder casually)
Header banner (name, aim, key-positions line, email, phone, city, social links) → quick-facts strip (availability, work eligibility) → Key Highlights (optional stat tiles) → Professional Summary → Education → Work Experience → Internships → Projects → Skills → Certifications → Training & Courses → Awards & Recognition → Extracurricular & Volunteering → Personal Details (optional, last: date of birth, address, nationality).
Rationale in `docs/2026-10-03-cv-builder-core.md`.

## Visibility rule
Edit mode shows every section (empty ones as "Add your…" placeholders). View mode shows a section only if `has.<section>(data)` is true, and hides empty fields inside it. List sections are visible when their array is non-empty.

## Data model (`CVData`, `schemaVersion: 1`)
`header` (name, headline, highlights, availability, workEligibility, nationality, visaStatus, email, phone, location, dateOfBirth, address, photo, `photos[]` (library of up to 6 uploaded photos, `photo` is the CV one) and `portfolioPhoto` ("" = same as the CV photo; migrate puts an old save's `photo` into the library), `links[]` = `{id, platform, url}`) · `summary` · `education[]` (degree, institution, current, yearOfStudy, courseLength, end, grades, coursework, notes) · `skills` (technical/languages/soft) · `theme` · `experience[]` and `internships[]` (title, company, from, to, `responsibilities[]`, `technologies[]`, `skills[]`, `outcomes[]`) · `stats[]` (value, label) · `projects[]` (organization, description, details[], tech[], from/to) · `certifications[]` (validFrom, validTill, lifetime) · `trainings[]` (completed) · `awards[]` · `extracurricular[]` (from/to). List items carry a stable `id`.
All dates are `"YYYY-MM"`; end dates may be `"present"`. Part-time jobs go in Work Experience (there is no separate part-time section).

## Migration
`lib/migrate.ts` handles earlier saves: single education object → `education[]`, free-text `description` → bullet `responsibilities`, text dates → `YYYY-MM`, `date`/`dates`/`duration` → new date fields. Add a new step there whenever a field is renamed.

## Themes and header style
`lib/themes.ts` holds 10 themes plus `THEME_GROUPS` (Conservative / Creative); the toolbar `ThemePicker` popover in `CVEditor.tsx` sets `theme` and `headerStyle` (`banner` | `classic`). `.header-classic` in `globals.css` overrides the banner's `text-white` / `bg-white/15` / `border-white` utilities, so when adding banner markup keep using those utilities (or add a matching override) and mark decorations with `.deco` and the accent line with `.hl`.

## Certifications and trainings
Two arrays (`certifications[]`, `trainings[]`), each entry with `display: "row" | "line" | "hide"`. Rows render compactly; `line` entries are folded into one "Other Trainings:" / "Other certifications:" line; `hide` entries stay in the data but are skipped in View/print. `mergeCertTraining` renders both in one "Certifications & Training" section with a type tag per entry. `has.certifications` / `has.trainings` ignore hidden entries.

## View mode, print options and ATS print (Phase 2)
Edit | View is the only mode switch (View = read-only, formerly "Preview"). The toolbar "Print options" popover (`components/PrintOptions.tsx`, own key `cv-builder:print-prefs:v1`) sets `style` (`bw` default | `colour`), `photo` (default off) and `personal` (include the Personal Details block, default on); `CVEditor` puts them on the root wrapper as `data-print` / `data-photo`, and `app/globals.css` styles the printout from those attributes inside `@media print`. Colour = the Phase 1 look; B&W = plain ATS-friendly text, 10.5 pt body, 14 pt headings, 24 pt name, own named `@page cvbw` with zero margin. ATS lessons that must not regress: keep `position: static` for positioned elements in B&W print (otherwise PDF text order scrambles) and keep ligatures off. Details and test method: `docs/2026-10-03-cv-display.md`.

## Skill filter, View mode only (Phase 3)
Clicking skills in the View-mode Skills section highlights (outline + "Matches: ..." badge) the experience, internship and project cards that mention any selected skill (OR logic); others are dimmed or, with "Show only matches", hidden. State is React-only in `CVEditor` (`selectedSkills`, `onlyMatches`), never saved; matching is whole-term, case-insensitive (`lib/filter.ts`). Rules that must not regress: Edit mode and the hidden measuring copy never get a filter; `TagList` keeps its Phase 1 local toggle unless `selected`/`onToggle` are passed; printing ignores filters through the `.fx-*` resets in `@media print` (no entry is ever removed from the DOM). Details and tests: `docs/2026-10-03-cv-filtering.md`.

## Export, versions and photo (Phase 4)
Toolbar **Export As** menu (`components/ExportMenu.tsx`): PDF (= the existing Print flow, never a screenshot PDF: that would break ATS text), Word `.docx` (`lib/export/docx.ts`, package `docx`; the shared options dialog in `ExportMenu` (`FormatDialog`, also used for HTML and PowerPoint): colour theme or B&W, photo, personal details, remembered in `cv-builder:word-prefs:v1`; coloured band, footer with page numbers, en-GB, links only for real URLs), HTML (`lib/export/html.ts`, one self-contained file), one-page landscape PowerPoint (`lib/export/pptx.ts`, package `pptxgenjs`, dynamic import: dark-theme sidebar + two content columns, each block positioned from a measured height; 10.5 pt default, detail trimmed before the font shrinks; black & white = white sidebar, no circles; see the doc before changing the layout constants), text, JSON (+ **Import JSON**, validated through `lib/migrate.ts`), LinkedIn text (LinkedIn's own field names; Languages separate from Skills; certifications with issue/expiry; `toLinkedIn(model, cv)`), e-mail draft (`mailto:`, no attachments possible), QR code (package `qrcode`; vCard of contact details, never date of birth or address, or any profile link). All renderers read one neutral model, `lib/export/model.ts`, which applies the View-mode visibility rules (empty entries/sections skipped, hidden certifications/trainings skipped, folded "Other ..." lines): change visibility rules there, not in each exporter. Word/text/LinkedIn honour the Print options (photo, personal details); text and LinkedIn never include the photo. File names come from `fileBase()` (`First_Last_CV.ext`); the PDF's name is set via the page title while printing (`beforeprint` / `afterprint` in `CVEditor`). **Versions**: `lib/versions.ts` + `lib/useVersions.ts` + `components/VersionsPanel.tsx`, own key `cv-builder:versions:v1`, newest first, no limit (storage warning above ~3.5 MB), statuses Current / Saved / Exported; loading or importing over unsaved work goes through `requestReplace` in `CVEditor` (offers "Save current first"). Dialogs use `components/Modal.tsx`, which portals into `#cv-root` so theme variables apply. Photo upload (`PhotoUpload.tsx`) accepts JPG, JFIF (a JPEG with another extension, also accepted by file name), PNG, WebP and GIF up to 2.5 MB (every photo is saved as a 240 px JPEG Base64 string); uploads are added to a library of up to 6 photos with a "Photos (n)" manager (Edit mode, hover the photo) to choose the CV photo and the portfolio photo separately; the portfolio uses `portfolioPhoto` through `portfolioCv` in `PortfolioShell`. Share links need a backend and are NOT built (decision pending: `docs/2026-10-03-sharing.md`). Details: `docs/2026-10-03-export-formats.md`.

## Portfolio website (Phase 5)
A separate, additive site around the CV under `/portfolio` (`/portfolio` home, `/cv`, `/projects`, `/contact`); the CV builder stays at `/` untouched (moving it would be a disruptive change: ask first). `app/portfolio/layout.tsx` wraps pages in `components/portfolio/PortfolioShell.tsx` (sticky header with the same nav everywhere, mobile menu, footer, theme CSS variables from the CV, and a context with the CV data). Data is read-only: `lib/portfolio.ts` reads the live CV from `localStorage` (`cv-builder:v1`, never written) and falls back to the published snapshot `public/portfolio-cv.json` (a CV Builder JSON export; visitors only ever see this one; it ships with demo content, replace it with your own export to publish). Projects, tech stack and the filter are derived from the CV (`projectViews`, `featuredProjects`, `techStack`); the CV page has two tabs: the one-page profile (`components/portfolio/OnePagerView.tsx` draws the item list from `layoutOnePager` in `lib/export/pptx.ts`, the same list the .pptx file is built from: keep the two in step by only changing the layout there) and the full CV (`components/portfolio/CVSheet.tsx`, from the Phase 4 `buildModel` output), reusing the Phase 4 exporters for downloads; print goes through the browser's Save as PDF on a named A4 page, with the portfolio chrome hidden by `print:hidden`. The contact form has no server: `mailto:` by default, or `fetch` to `NEXT_PUBLIC_CONTACT_ENDPOINT` when set; client-side validation plus a honeypot. Looks: six presets (A teal+gold default, B coral, C light hero, D navy, E black+gold, F slate+gold) in `lib/portfolioTheme.ts`, with their OWN colours (not tied to the CV theme unless the file sets `"base": "cv"`), chosen by the optional `public/portfolio-theme.json` (`look`, `base`, `accent`, `hero`, `floatingCards`; invalid or missing falls back), overridable with `?look=` and, in the owner's preview only, the A-E buttons (`portfolio:look`); colours are CSS variables on `.pf-root` plus `data-hero`, styles and animations in `app/portfolio/portfolio.css` (reduced-motion safe). Rules: keep every portfolio style and class inside `app/portfolio` / `components/portfolio` (no edits to `app/globals.css`, the editor, `lib/types.ts` or `lib/migrate.ts` without approval), never write to builder storage, and keep public pages free of anything the CV owner has not put in the CV. Details: `docs/2026-10-03-portfolio.md`.

## Job Matcher (Phase 6)
New page `/job-matcher` (`app/job-matcher/page.tsx` + `components/jobmatch/JobMatcher.tsx`), opened from one new plain-link button "Job Matcher" in the builder toolbar (full page load so the editor saves first). Flow: upload (PDF, DOCX, JSON, HTML, XLSX, TXT, PPTX; 5 MB) or paste (5,000 chars) -> analyse -> review -> tick suggestions -> before/after -> "Create aligned version". Parsing is browser-side in `lib/jobmatch/parse.ts` (pdfjs-dist for PDF; JSZip reads the XML of docx/pptx/xlsx, so no SheetJS/mammoth). Analysis: `POST /api/analyze-job` (`app/api/analyze-job/route.ts`, Node server only) calls Anthropic (default model `claude-sonnet-5-5`, `ANTHROPIC_MODEL` to change) or an OpenAI-compatible service (`LLM_PROVIDER=openai`) with the key from `.env.local` (copy `.env.example`; `.env*` is git-ignored, never commit keys). **Safety rules that must not regress:** in production the route is OFF unless `JOB_MATCHER_ACCESS_CODE` is set (else anyone could spend the owner's credit), 10 requests per 10 minutes per address, 600 KB body and 60 s limits; the client strips photo(s), name, e-mail, phone, address, date of birth, nationality, visa and links before sending (`cvForAi`, and `sanitizeCv` in `lib/jobmatch/prompt.ts` again on the server) and the user must tick a consent box; the system prompt forbids inventing anything and treats the job text as data. Everything the model returns passes `lib/jobmatch/validate.ts`: numbers clamped, text capped, and each suggestion's `op` is checked against the real CV (ids, skills, bullet indexes) or downgraded to advice-only. Only five change kinds exist (`Op` in `lib/jobmatch/types.ts`: reorder skills, reorder items, reorder bullets, rewrite summary, rewrite headline) so applying one can never add a fact; text rewrites start unticked and editable. Without a key the **basic keyword matcher** (`lib/jobmatch/basic.ts`, runs in the browser, same result shape) is used. Storage: jobs in `cv-builder:jobs:v1` (last 20), aligned versions are normal saved versions with an optional `jobId` (`lib/versions.ts`); the working CV is only replaced by the explicit "Open it in the CV builder" button, after saving the old one as a version. Not to be used on static-only hosting (GitHub Pages): the AI route needs a server. **Tailored CVs**: the picker "Which CV should I use?" chooses the base (working CV or any saved version); `POST /api/tailor-cv` (`app/api/tailor-cv/route.ts`, shares access rules and the rate limit with analyze-job through `lib/jobmatch/server.ts`) returns a plan that `lib/jobmatch/tailor.ts` reduces to existing ids and existing skill names, then `changesFrom` flags any new number, known tool name or proper name (`unsupportedClaims`) and switches those changes off; `components/jobmatch/TailorPanel.tsx` is the review screen; the result is saved as a normal version with `tailored: true`, `basedOn` and `jobId` (label "Tailored" in `VersionsPanel`) and is viewed and exported in every format at `/job-matcher/cv?id=` through `components/portfolio/CvViewer.tsx` (also used by the portfolio CV page). Never let a tailoring path add content that is not in the base CV, and never write over the base CV or the working CV without the explicit open-in-builder confirmation.

## Page counter
`CVEditor` renders `CVDocument` twice: the visible one, and a hidden 794 px-wide View copy measured with `ResizeObserver` (`PAGE_PX` = 277 mm of A4 at 96 dpi). Pages = ceil(height / PAGE_PX). Print CSS: `@page { size: A4; margin: 10mm 0 }`, card forced to 210 mm. Cards use `break-inside-avoid`.

## Styling
Theme CSS vars on the root wrapper: `--accent` (fills, bars, banner), `--accent2` (banner gradient end), `--tint` (light backgrounds), `--ink` (darker shade for text/buttons on white; use it instead of `--accent` for text). The name `<h1>` uses `.name-trim` so the photo's top edge matches the top of the capital letters.

## Gotchas
- `Editable` is uncontrolled: never pass changing `key`s to it, and do not make it render `value` as children (caret would jump).
- Render the editor only after `useCV` has loaded (avoids SSR/localStorage hydration mismatch).
- Expected graduation assumes a September start: `Jun (start year + courseLength)`.
- On Windows, edit files with the Edit/Write tools; Python's default `open()` encoding (cp1252) corrupts non-ASCII characters like `—` and `…`.
