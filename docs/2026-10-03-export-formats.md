# Export formats, versions and photo upload (Phase 4)

All of this is client-side and additive. Nothing here changes the editing screens, the saved CV data (`cv-builder:v1`) or what the print/PDF output looks like.

## Where things are (Word, HTML and PowerPoint share one options dialog)
Toolbar: **Export As ▾** (always visible, works on a phone), **Versions (n)**, the existing **Print options** and **Print**. The status line shows `Version: <name or Working copy>` and "(edited)" when the CV differs from the loaded version. A toast confirms actions ("Word document downloaded", "LinkedIn text copied to clipboard", ...) and shows "Exporting Word document…" while a file is being prepared.

## Why each format exists and how to use it
All file names are `FirstName_LastName_<Type>.<ext>` (first and last word of the name; `CV` if there is no name). Text and LinkedIn follow the Print option "Include personal details" and never contain a photo. **Word has its own options dialog** (see below).

| Export | Why it exists | How to use it |
|---|---|---|
| **PDF** (existing, `Name_CV.pdf`) | The file most employers want. Real text, clickable links, black & white ATS version or colour. | Export As → PDF (same as the Print button): choose destination **Save as PDF** (the browser's own, not "Adobe PDF" or "Microsoft Print to PDF"). The file name comes from the page title, which is set to `First_Last_CV` while the print dialog is open. A one-click PDF download was deliberately not built: generating a PDF from a screenshot of the page would make the text unreadable for ATS, which is exactly what Phase 2 fixed. |
| **Word** (`.docx`) | Recruiters and agencies sometimes ask for Word; also the easiest way to hand-edit the final wording. | Export As → Word Document opens a small dialog: **Colour (your theme)** or **Black & white**, **Include photo** (disabled with a hint until a photo is uploaded) and **Include personal details**. Your last choices are remembered (`cv-builder:word-prefs:v1`); the Print options are only the first starting point. Colour mode gives an **edge-to-edge coloured header band** (like the PDF) with the photo at the left and white text. To reach the page edges the band table is wider than the text area (negative indent plus a small overhang that Word clips), with cell margins that put its text back in line with the body text; the band is its own first section with a ZERO top margin (its top padding stands in for the margin), followed by a continuous section with the normal 0.5 in margin, which Word applies from page 2 on. So the colour really starts at the top edge: no picture, no header content, nothing to delete or that Word could fade. (An earlier page-header strip showed faded in Word, and a floating picture did not show at all.) The availability / right-to-work strip text starts at the photo's left edge (not the name's), so the two facts fit on one line; the Word table uses a fixed layout so the columns cannot be re-sized by Word. The photo is nudged down so its top lines up with the top of the name's capital letters. Your name and contact details stay in the body (editable, and readable by tools). Word (2013 or newer, compatibility mode 15) shows it edge to edge; some viewers and previewers clip tables at the margin, and a physical printer cannot print the outer 4-5 mm, so a thin white edge may show on paper. (With the Classic header style there is no band: a white header with a coloured rule instead), a tinted availability strip, themed headings, rules, bullets and links. Every file has: A4, Calibri 10.5 pt, 0.6-inch side and 0.5-inch top/bottom margins (the same as the PDF; Word's 1-inch default made a dense CV look like a narrow column, so this replaces the 1-inch margin first specified), real headings and bullet lists, title line then company line with the date at the right edge, clickable links (only for real web addresses, so text such as "test twitter URL" stays plain), a **footer** with your name and "Page X of Y", and UK English (en-GB) set for Word's spell-check. Same sections, order and hiding rules as View mode. In colour mode the availability strip is the second row of the same table as the header band, so its left and right edges line up exactly with the band (an earlier version used a separate indented paragraph and sat slightly inside it). Checked by reading the file back and by rendering it with a Word-compatible previewer; the right-aligned dates and the footer page numbers can only be seen in Microsoft Word itself. |
| **HTML** (`.html`, `First_Last_CV.html`) | One self-contained web page you can e-mail, open in any browser, host on a personal site or keep as a lightweight archive. | Export As → HTML Page; same options dialog as Word (colour theme or black & white, photo, personal details; remembered separately in `cv-builder:html-prefs:v1`). One file: CSS and the photo (Base64) are inside, no external requests, no scripts. Semantic headings and lists, clickable e-mail and profile links, responsive (checked at 390 px), `lang="en-GB"`, and an `@media print` stylesheet (A4, 12 mm margins, colours kept, headings kept with their content), so it also prints to a clean PDF. All text is HTML-escaped. |
| **One-page PowerPoint** (`.pptx`, `First_Last_OnePager.pptx`) | A single landscape slide for sharing quickly (a chat, an e-mail, a meeting, a screen), modelled on a one-page profile: 13.33 x 7.5 in, three columns. | Export As → One-Page PowerPoint; same options dialog (remembered in `cv-builder:ppt-prefs:v1`). **Design (colour):** a dark theme-colour sidebar on the left (shade of your theme, soft circles kept inside it) with a gold-ringed circular photo, large white name, headline, key positions as gold-outlined chips, availability / right to work with gold dots, **Key Highlights** as translucent tiles (gold value, small label) and **Skills**; a white main area with small capital section headings (gold marker, theme colour, thin rule), the Professional Summary in a soft tinted box with an accent bar, a timeline (dots and a thin line) for Education, Work, Projects, Awards and Extracurricular with the date as a pill on the title line, and light cards for Certifications and Training. **Black & white:** the same layout, white sidebar, black text, outlined chips and tiles, no circles or colour. **Placement (as arranged by the owner):** left = photo, name, headline, key positions, availability, Key Highlights, Skills; middle = Professional Summary, Education, Work Experience, Internships, Projects; right = Certifications and Training, Awards, Extracurricular, Personal Details, then a **Connect** bar (contact and clickable links) at the bottom. All text is real, editable PowerPoint text (Calibri) on simple shapes; the only picture is the photo. **Fitting on one page and font size:** 10.5 pt is the default. PowerPoint does not shrink text on opening, so the app measures every block (Calibri measured at about 0.405 em per character, 6% safety added) and, to keep 10.5 pt, shortens detail step by step (fewer bullets per entry, outcomes and descriptions trimmed) and tells you ("Some details were shortened to fit on one page"); only if that is not enough does it go below 10.5 pt (down to 7 pt); if even that cannot fit it says the end is cut off. A CV with fewer entries keeps all its detail. Checked by reading the file back (one slide, text inside the slide, links, alt text on the photo) and by rendering it with a previewer (which shows the photo square and ignores some details); I could not open the file in PowerPoint itself, so check the result there. |
| **Text** (`.txt`) | Application forms and ATS boxes that only take plain text; also e-mail bodies. | Export As → Text File. ASCII punctuation, clear UPPERCASE section headers, `-` bullets, no photo. |
| **JSON** (`.json`) | A full backup and a way to move your CV to another computer or tool. | Export As → JSON. Contains an `app` marker, a `format` number, `exportedAt` and the complete CV (including the photo). Restore with **Import JSON…** (same menu): the file is validated and upgraded by the same `lib/migrate.ts` used for saved data, and if your current CV is not saved as a version you are asked whether to save it first. A bad file shows an error and changes nothing. |
| **LinkedIn format** (`First_Last_LinkedIn.txt`) | LinkedIn cannot import a profile from a file, so the useful thing is text laid out for its fields. | Export As → LinkedIn Format: instructions "Copy text below → Paste into LinkedIn profile", then Headline (220-character limit shown), About (2,600 limit shown), Experience (title/company/dates/description), Skills, and the other sections. Buttons copy the headline, the About text or everything; or download the .txt. |
| **E-mail** | Quick way to send your CV text to a recruiter. | Export As → Send Email: enter an address (optional); subject is pre-filled `My CV - <Name>`, the body holds your CV as text (cut at about 1,800 characters because many mail apps shorten longer links; "Copy full CV text" copies everything). A web page cannot attach files to an email, so to attach the PDF: Save as PDF first, then attach that file to the draft. |
| **QR code** | Job fairs, networking events, business cards. | Export As → QR Code: choose a **contact card** (vCard: name, headline, email, phone, profile links; never date of birth or address) or any profile link, or any text. Download PNG or Print. Verified by decoding the generated image back to the original text. |

## Versions
- **Save Version** asks for a name (suggested: `<Name> - <date>`), stores a full snapshot (CV data including the photo, theme and print-affecting settings that live in the CV), newest first, in `localStorage` key `cv-builder:versions:v1`.
- The sidebar lists name, date and time, and status chips: **Current** (identical to the working CV), **Saved**, **Exported** (an export was made while it was the current CV).
- **Load** replaces the working CV. If the working CV is not identical to any saved version you are asked: *Save current first* (stores it as "Auto-saved before loading ...", then loads), *Replace without saving*, or *Cancel*. **Delete Version** asks for confirmation.
- There is **no limit** on the number of versions. The only limit is the browser's storage (about 5 MB shared with the CV): the sidebar shows the approximate size, warns above about 3.5 MB, and if storage is full the save fails with a message and nothing is lost.
- Selected skill filters and the Print options are not part of a version.

## Photo upload
The photo upload from Phase 1 already existed (header, click to add, Change / Remove, shown in Edit, View and print, stored as a Base64 string with the CV). Phase 4 added checks and fixed two bugs: only **JPG, PNG, WebP or GIF** are accepted; files over **2 MB** are rejected with the file's size; errors are shown next to the photo. Transparent images used to turn black (JPEG has no transparency): a white background is now painted first. A failed upload no longer wipes an existing photo. The photo is cropped to a square and stored as a 240 x 240 JPEG (about 10-40 KB), so GIFs become still images. The header shows it at 80 px; a larger 200 x 200 preview was not added.

## Storage strategy and limits
- Everything is in `localStorage` (about 5 MB per site in most browsers, shared by all the keys below). One CV with a photo is typically 15-50 KB; each saved version includes its own copy, so 20 versions are roughly 0.3-1 MB and a hundred can approach the limit. The sidebar shows the approximate size.
- Keys: `cv-builder:v1` (working CV), `cv-builder:versions:v1` (history), `cv-builder:print-prefs:v1` (print choices).
- Clearing browser data deletes all of it: export a JSON backup.

## Future upgrade path
- **Cloud storage for photos and versions** (needs a backend and sign-in): store images as files (object storage) and keep only a URL in the CV; sync versions per account.
- **Shared links** need a backend (see `docs/2026-10-03-sharing.md`).
- A proper PDF/DOCX server renderer for pixel-identical output, if ever needed.

## Code map
`lib/export/model.ts` (one reading-order description of the CV: skips empty entries and hidden/folded certifications, same as View mode), `lib/export/formats.ts` (text, LinkedIn, JSON, import, file names, downloads), `lib/export/docx.ts` (Word, using the `docx` package), `lib/versions.ts` + `lib/useVersions.ts` (storage and logic), `lib/export/html.ts` (HTML), `lib/export/pptx.ts` (one-page PowerPoint, package `pptxgenjs`, loaded only when used), `components/ExportMenu.tsx` (menu, the shared Word / HTML / PowerPoint options dialog, LinkedIn / e-mail / QR dialogs, JSON import), `components/VersionsPanel.tsx`, `components/Modal.tsx`, `components/PhotoUpload.tsx`. New dependencies: `docx` (Word) and `qrcode` (QR images).
